## Measured before/after

*Filled at close.* Captured so far:

**The outage and its recovery (item 1).** Extraction failed 100% from 2026-08-18 06:19 UTC and was
billed for every failure.

| | During the outage | First day with the fix (08-22) |
|---|---:|---:|
| Postings extracted | **0** for four days | **428** |
| Anthropic spend | $5.20 / $4.66 / **$14.26** per day | **$3.10** metered across three runs |
| What `pipeline_runs` reported | `extraction_calls = 0`, ~$0.08 | $2.44 · $0.65 · $0.007 per run |
| New roles mailed, all recipients | **3** (08-21) | **219** (08-22) |

The $3.10 decomposes as a one-off recovery batch ($2.44, 325 extractions + 618 matches), its tail
($0.65, 102 extractions), and steady state resuming ($0.007, 1 extraction). It is self-limiting, not
a new run-rate. A further ~$2 was burned invisibly by the 02:01 UTC run, which had already started on
the old image when the merge landed at 02:43.

**The repair is load-bearing, not historical.** `repaired stringified structured output … (fields:
stack)` fired **9 times on 08-22 alone**, most recently 14:17. The provider is still intermittently
returning stringified values; D-112 is actively rescuing those extractions rather than having fixed a
past event. If the native path returns, the log line stops on its own.

**The circuit breaker did not trip, and the backlog is genuinely drained.** Extractions per run decay
325 → 102 → 1. Of the 6,685 open unextracted rows inside the age floor, **zero pass the Stage-A scope
gate** (checked by running the real gate against every one), so the residue is permanent rejects, not
unfinished work.

**The dropped digest (item 2).** `vja-digest-trigger` last attempt 2026-08-22T11:00:01Z, status code
**14** (`UNAVAILABLE`), **no execution created**. Detected ~2h late by the 26h absence policy;
recovered manually at 14:27 (36 sent, 4 paused, 1 skipped, 219 new roles, 3 min).

## Known and not fixed

- **Alert-on-silence still does not exist**, carried from 1.2 and unchanged. It remains the item most
  responsible for the four-day outage, and it still needs design: the permanent Stage-A residue means
  "backlog non-empty" is always true.
- **The digest absence window still detects a miss ~2h late** (26h against a ~24h cadence). Narrowing
  it needs delete-then-recreate, because `alerts.sh` is idempotent by `displayName` and silently
  no-ops an edit.
- **Durable cross-execution delivery idempotency is still unbuilt** (D-086's named follow-up). D-113's
  600s backoff is what carries the no-double-send guarantee in its place; a uniqueness claim on
  `(vertical, recipient, send date)` would make retry timing irrelevant, at the cost of a migration.
- **Workday detail fetches 303-redirect to a maintenance page during Workday's own maintenance
  windows** (observed across ~20 employers during the 08-22 06:00 run). These cost nothing — they fail
  before any LLM call — but they *do* count toward D-112's consecutive-failure breaker, so a long
  enough Workday outage could abort a vertical's extraction stage for a reason that is not about
  spend at all. Not observed to trip; noted because the breaker counts all exceptions, not just billed
  ones.
- **The whole rejected corpus is still re-read six times a day** (6,685 rows, zero survivors) and
  **`pipeline_runs` still records no run duration**. Both carried from 1.2; both are small.
- **GCP budget alert and the Anthropic credit balance**, carried from 1.2 and from 1.1 before it.
